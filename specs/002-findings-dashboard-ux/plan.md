# Implementation Plan: Findings Dashboard — Presentation & UX v2

**Branch**: `002-findings-dashboard-ux` | **Date**: 2026-09-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-findings-dashboard-ux/spec.md`

## Summary

v2 makes the *same* findings data look and behave like a tool: the existing
stdlib-only Python generator (`dashboard/`) emits a redesigned
`site/index.html` with a persistent sticky navigation, a designed visual
hierarchy (distinct header, separated headed views, tier/status grouping,
text-and-shape badges meeting WCAG 2.1 AA), corrected multi-metric comparison
charts (value axis, gridlines, zero clipped labels), and inline client-side
filter/search/sort that never touch the filesystem or the generated bytes.
Every v1 guarantee — evidence-backed values, tooltips, stale flags with
non-zero exit, read-only behaviour, self-containment, determinism, deep
links — is preserved (FR-001). All settled design decisions were made with
the owner during `/speckit.specify`; no NEEDS CLARIFICATION items remain.

## Technical Context

**Language/Version**: Python 3.14 (repo runs on Homebrew `python3`; stdlib
`tomllib` requires ≥ 3.11) — unchanged from v1

**Primary Dependencies**: none — stdlib only (`json`, `tomllib`, `html`,
`xml.etree.ElementTree` for tests, `pathlib`, `re`, `datetime`, `unittest`).
No charting library, no JS framework, no build toolchain (spec FR-011;
constitution III, VI). Interactivity is hand-written inline JavaScript
emitted as a static string by the generator.

**Storage**: files — reads `findings/*.toml` (curated layer, unchanged),
`results/*.json` (append-only record, unchanged), `docs/FINDINGS.md`
(anchors, unchanged); writes exactly one artifact: `site/index.html`
(committed, FR-015). No new persistent data of any kind (spec Key Entities:
filter/sort state is view-time and browser-only).

**Testing**: `unittest` (stdlib) in the existing `tests/` directory — v1
created the suite (8 files); v2 extends it with structural tests for
navigation, filter/sort data attributes, SVG no-clip geometry, and computed
WCAG contrast ratios. Constitution VII mandates red-green-refactor.

**Target Platform**: macOS (M5 Max / 128 GB); the site is viewed in any
modern browser from `file://` — unchanged from v1

**Project Type**: CLI generator + static single-page site (internal tool,
single local user, no hosting) — unchanged from v1

**Performance Goals**: generation < 5 s against current data volume
(non-regression, spec SC-008); in-browser filter/sort/search responds
instantly on the current DOM size (≤ ~50 findings, a few hundred table rows)

**Constraints**: read-only w.r.t. `results/`, `profiles/`, and the oMLX
configuration (FR-015); no network at generation or view time, all assets
inline in the single HTML file (FR-011); deterministic output with the
"generated at" stamp as the only allowed difference (FR-013); WCAG 2.1 AA
(FR-014); no filesystem mutation or state persistence from the browser
(FR-012); progressive enhancement — full content readable with JavaScript
disabled (FR-010)

**Scale/Scope**: 16 findings files (3 shipped lineup, 2 retired, 11
dead-end), one HTML page with three views plus a nav/control bar; new code
is two modules (`charts.py`, `assets.py`) plus a rewrite of `render.py`'s
page assembly; `findings.py`, `sources.py`, `generate.py` are unchanged

**Structure Decision**: v1's four-module package is kept; v2 splits the two
concerns that `render.py` would otherwise bloat past ~700 lines:
`charts.py` owns all SVG geometry (the no-clip guarantee is a testable
pure function of its inputs — research.md R3), and `assets.py` owns the
static CSS/JS strings (determinism is trivially verifiable — they are
constants; research.md R1). `findings.py`, `sources.py`, and `generate.py`
are untouched: the spec requires no data-model or CLI change (FR-001), and
the exit-code contract (0/1/2) is part of the v1 guarantees. No `src/`
layout, no web framework, no assets directory — the site remains one
self-contained file (v1 research R5).
