# Implementation Plan: Findings Dashboard

**Branch**: `001-findings-dashboard` | **Date**: 2026-09-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-findings-dashboard/spec.md`

## Summary

A curated, evidence-backed dashboard for the local-LLM stack: a single
self-contained `site/index.html` (opens from `file://`, no network, no server)
generated by a stdlib-only Python CLI from a new `findings/` layer (one small
TOML file per finding) plus the existing `results/*.json` measurements. Every
displayed number is resolved from its named source file + path at generation
time and carries a hover/keyboard-focus tooltip (what / how / evidence, plus
links to the FINDINGS.md section and the raw results file). Three views: live
lineup (tables plus simple inline-SVG comparison charts), candidate status
board, settled dead ends. A missing or schema-drifted source renders a visible
stale marker and a non-zero exit — never a silent wrong or absent number.

## Technical Context

**Language/Version**: Python 3.14 (repo runs on Homebrew `python3`; stdlib
`tomllib` requires ≥ 3.11)

**Primary Dependencies**: none — stdlib only (`json`, `tomllib`, `html`,
`pathlib`, `re`, `datetime`, `unittest`). No third-party packages. The
spec's "charting library" assumption is satisfied with zero dependencies:
charts are inline SVG generated in Python (research.md R2).

**Storage**: files — reads `findings/*.toml` (curated layer) and
`results/*.json` (append-only record, ~189 files); writes exactly one
artifact: `site/index.html`, which is committed (FR-015, clarification Q3)

**Testing**: `unittest` (stdlib) in a new `tests/` directory — the first tests
in this repo. Constitution VII mandates red-green-refactor; tasks will be
ordered test-first.

**Target Platform**: macOS (M5 Max / 128 GB); the site is viewed in any modern
browser from `file://`

**Project Type**: CLI generator + static single-page site (internal tool,
single local user, no hosting)

**Performance Goals**: generation < 5 s against current data volume (SC-004;
~189 results files, seed findings set)

**Constraints**: read-only w.r.t. `results/`, `profiles/`, and the oMLX
configuration (FR-010); no network at generation or view time (FR-011);
deterministic output with exactly one exception — the invocation-time
"generated at" stamp (FR-012, clarification Q1); no new third-party
dependencies (constitution III)

**Scale/Scope**: ~189 results files (134 when the spec was written), ~15–20
seed findings (FR-013), one HTML page with three views

### Source Code (repository root)

```text

├── findings.py          # load + validate findings/*.toml (FR-002, FR-007)
├── sources.py           # resolve file + path expression against results/ (FR-005, FR-008)
├── render.py            # HTML + inline SVG rendering, tooltips, stale markers (FR-004..012)
└── generate.py          # CLI entry: python3 dashboard/generate.py (FR-001)

findings/                # curated findings layer — one small TOML file per finding
└── *.toml               # seeded for v1 per FR-013

site/
└── index.html           # generated artifact, committed (FR-015)

tests/                   # first tests in this repo (Constitution VII)
└── test_*.py            # unittest, stdlib only
```

**Structure Decision**: flat top-level packages, matching the repo's existing
layout (`bench/`, `profiles/` are flat script packages). The generator is a
four-module package because the spec's failure modes (validation vs. stale vs.
rendering) are distinct testable units; `generate.py` stays a thin CLI entry
in the house style of `bench/report.py` (plain script, `main() -> int`,
`raise SystemExit(main())`). No `src/` layout, no web framework, no assets
directory — the site is one self-contained file.
